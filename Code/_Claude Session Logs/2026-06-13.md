### Сделано: auth — CSRF + grace-период (безопасность-критичные части)
- Топология: фронт и API на разных origin (нет статик-раздачи в Express) → CSRF обязателен.
- **CSRF (middleware/csrf.js):** signed double-submit (HMAC, без зависимостей). Защищает cookie-сессию; Bearer (тесты/API) и анонимные пропускаются. **Дыра CSRF закрыта уже сейчас** независимо от клиента: forged cookie-only мутация (без Bearer и X-CSRF-Token) → 403. csrf-token endpoint + CORS-заголовок + testApp обновлены.
- **Grace-период refresh:** `RefreshToken.rotated_at` + `REFRESH_GRACE_MS` (30с). Параллельные вкладки не разлогиниваются; reuse после окна → 401.
- Тесты: `tests/csrf.test.js`, `tests/refreshGrace.test.js`. Бэкенд **321/321**, lint чистый. Env: CSRF_SECRET, REFRESH_GRACE_MS в .env.example.
- **Решения пользователя:** «начать auth сейчас», refresh-гонка = grace-период.
- **Осталось (staging):** клиент cookie-only (убрать Bearer/in-memory токен, CSRF-интерцептор, socket → cookie-handshake). Это уже XSS-хардненинг (токен и так не в localStorage), требует браузерной проверки. Детали в [[Finance — План миграции Auth (cookie + CSRF)]].
