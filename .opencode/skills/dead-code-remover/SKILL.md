# dead-code-remover — поиск и удаление мёртвого кода

## Триггеры
- `"удали мёртвый код"` / `"dead code"`
- `"найди неиспользуемое"` / `"почисти код"`
- `"что не используется"`

## Известные кандидаты (из TZ_v3 аудита)

| Элемент | Где | Тип |
|---------|-----|-----|
| `showCelebration` | `client/.../GoalsWishes.jsx` | неиспользуемая переменная/состояние |
| Кнопка «Досрочное погашение» | `client/.../Debts.jsx` | не реализована (нет обработчика) |
| Кнопка «Подробнее» | `client/.../SafetyPillow.jsx` | не реализована |

| Дублирующая ветка `PrismaClientKnownRequestError` | `lib/errors.js:~119` | dead branch (дубль строки 113) |
| `errorTranslations.VALIDATION_ERROR` | `lib/errors.js:~129` | несуществующий ключ |
| Мёртвый код Sequelize/Mongo | `lib/errors.js:83-85` | остатки от другой ORM |

## Порядок работы

### Шаг 1 — автоматический поиск (бэкенд)
```bash
npm run lint            # no-unused-vars ловит часть мёртвого кода
```
Поиск функций, на которые нет ссылок:
```bash
# для подозрительной функции foo — проверить использование
grep -rn "foo" services/ controllers/ routes/ lib/ jobs/
# если единственное совпадение — определение → мёртвая
```

### Шаг 2 — проверка перед удалением (ОБЯЗАТЕЛЬНО)
Для каждого кандидата:
1. `grep` имени по ВСЕМУ репо (вкл. `client/`, тесты, `routes/`)
2. Проверить динамические вызовы: `obj[name]`, строковые ключи, реэкспорты
3. Для роут-функций — проверить, что нет маршрута в `routes/`
4. Для CSS — `grep` className по `client/src/`

### Шаг 3 — удаление (по одному, с проверкой)
- Удалить элемент
- `npm run lint` + `npm test` (бэкенд)
- Для клиента: `cd client && CI=true npx react-scripts test --watchAll=false`
- Одноразовые скрипты — НЕ удалять, а перемещать в `scripts/_Archive/`

## Важно
- ⚠️ НИКОГДА не удалять без grep по всему репо — функция может вызываться динамически
  или из клиента/тестов
- Одноразовые миграционные скрипты (`fix_scope.js`) — в `_Archive/`, НЕ удалять
  (могут понадобиться для истории/повтора)
- Удалять по одному элементу + прогон тестов после каждого — чтобы точно знать,
  что именно сломалось, если сломалось
- `lib/errors.js` правки — критичны (обработка всех ошибок API), тестировать особенно тщательно
- Клиентский мёртвый код (кнопки/CSS) — отдельно от бэкенда, свой тест-раннер
