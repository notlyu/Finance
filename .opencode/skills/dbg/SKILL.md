# dbg — Debug-помощник

## Триггеры
- `"дебаг"` / `"ошибка"` / `"баг"`
- `"не работает"` / `"сломалось"`
- `"помоги найти проблему"`
- `"что не так"` / `"почему"`

## Процедура

### Шаг 1: Сбор информации
- Прочитать сообщение об ошибке и stack trace
- Если ошибка в ответе API — проверить status code, body, headers
- Если ошибка в тестах — прочитать вывод тестов

### Шаг 2: Локализация
- Определить файл и строку из stack trace
- Прочитать соответствующий controller/service/middleware
- Проверить какие данные приходят на вход (req.body, req.params, req.query)
- Проверить что возвращает БД (если есть SQL/Prisma запрос)

### Шаг 3: Поиск паттерна
- Поискать аналогичные ошибки в тестах (`grep` по error message в `tests/`)
- Проверить есть ли уже фикс в коммитах (`git log --oneline --grep`)
- Проверить есть ли TODO или FIXME рядом с местом ошибки

### Шаг 4: Гипотеза и фикс
- Сформулировать гипотезу: что пошло не так и почему
- Предложить конкретный фикс с кодом
- Если фикс сложный — сначала спросить подтверждение

## Формат ответа

```
🔍 Debug Report
━━━━━━━━━━━━━━━
Файл: path/to/file.js:42
Ошибка: [текст ошибки]

Контекст:
  [что делает этот код]
  [какие данные приходят]

Гипотеза:
  [что пошло не так]

Фикс:
  [конкретное изменение]
```

## Известные паттерны ошибок (по результатам аудита)

| Симптом | Вероятная причина | Файл |
|---------|-------------------|------|
| `409 Conflict` при DELETE записи | Нет `onDelete` в Prisma → FK violation | `prisma/schema.prisma` |
| `500` вместо `404` / `400` | Контроллер использует `throw new Error()` вместо `AppError` | `accountController.js`, `debtController.js` |
| `╨í╨║╤Ç╤ï╤é╨╛` в JSON ответе | Mojibake (битая кириллица) | `services/transactionService.js:89` |
| `Cannot set headers after they are sent` | `notifyGoalReached().catch(next)` после `res.json()` | `controllers/goalController.js:499` |
| `null` в scope / неверная фильтрация | `scopeMiddleware` мёртвый код — никто не читает `req.scope` | `middleware/scopeMiddleware.js` |
| `TypeError: Cannot read properties of undefined` | `req.body` вместо `req.validated` (нет Zod-валидации) | `goalController.js:227`, `budgetController.js:303` |
| Медленный ответ на GET-запрос | N+1 запросы или отсутствующий индекс | `transactionService.js:438`, `csvImportService.js` |
| Данные записались не полностью | Нет `$transaction` — partial write после сбоя | 6+ мест (см. ТЗ раздел 6) |
| Тест ожидает 500 вместо 404 | Некорректное ожидание в тесте | `tests/accounts.test.js:81` |

## Что проверять в первую очередь (чеклист)

- [ ] `req.scope` установлен? (scopeMiddleware — мёртвый код!)
- [ ] `req.validated` используется или `req.body`? (Zod bypass)
- [ ] Валидация Zod: схема соответствует данным?
- [ ] Prisma: `null`/`undefined` в полях?
- [ ] Scope фильтр в Prisma запросах?
- [ ] Auth middleware: токен жив?
- [ ] Family role: достаточно прав?
- [ ] Есть ли `$transaction` вокруг нескольких write-операций?
- [ ] `res.json()` вызван до асинхронного колбэка с `next(err)`?

## Важно
- Не менять код без подтверждения пользователя
- Если не удалось найти причину — честно сказать
- Если ошибка известная — сослаться на pinboard или прошлые фиксы
